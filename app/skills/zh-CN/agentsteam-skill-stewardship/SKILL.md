# 经验沉淀

主动把当前工作中得到证据支持的经验写进技能，让下一次同类任务能直接采用有效的方法。技能保存一类任务的操作顺序、具体工具与命令、决策点、验证方法和会反复踩到的坑。

在当前 agent loop 中识别信号、检查证据、读取技能、写入并核验，完成后继续原任务或交付结果。沉淀正文和结果报告使用用户的语言，与所加载技能包的语言无关。

## 经验信号

出现以下任一信号，立即判断并处理对应经验：

- 非平凡的技术、修复、替代方案、排查路径或工具使用模式已经奏效，下次同类任务可复用。
- 对照测试、工具结果或实际代码，发现本轮使用的技能有错误、缺步骤、条件不完整或内容过时。
- 原有方法经过验证得到改进，例如找到了更短的可靠排查顺序，或明确了某个步骤必须满足的前提。
- 用户明确要求从刚才的经历、代码、资料或指定来源学习方法并保存。

有有效信号就采取行动，不能只在回复里说“下次会注意”。没有新经验时继续原任务；沉淀数量由证据决定。

## 目标技能库

维护**类别级技能**：主文件保存这一类任务共同需要的流程和判断，少量支持文件保存专题深度。一次经历的价值在于改善这类任务的做法。

按以下顺序选择第一个合适的位置：

1. **修订当前已用的个人技能。** 它已经参与了本次工作；如果覆盖这条经验，重新读取维护源并直接补全或纠正相应步骤。
2. **修订已有类别技能。** 当前已用技能不适用时，查找其他覆盖这类工作的个人技能，补步骤、决策点或触发条件。
3. **增加专题支持文件。** 类别已经存在而某个分支需要更多细节时，先扩展已有专题，再考虑新增引用、模板或脚本，并补主文件指针。
4. **创建新类别技能。** 确认现有技能均不覆盖后，使用任务类别命名；名称应在下一次同类任务中仍有意义。

## 执行流程

1. **定位证据与维护源。** 从当前协作中的实际操作、代码核对或验证结果形成候选，读取[资格与边界](references/eligibility.md)。采用身份上下文或用户明确指定的个人技能维护目录。
2. **明确一条经验。** 写清适用条件、有效动作、机制原因与验证办法。证据不足就停止该候选；多条独立经验逐条处理，每条分别判断与查重。
3. **读取并决定。** 按上述优先级选择位置，执行[读取、判断与写入](references/read-write-workflow.md)：检查完整个人技能清单，重读相关主文件与待改支持文件，判断停止、修订或新增。
4. **编写最小有效更新。** 应用[技能编写](references/authoring.md)的步骤、陷阱和文件组织要求。直接修正原有规则，保留无关内容；一次把当前候选改清楚。
5. **落盘并核验。** 使用当前 Harness 实际提供的文件工具写个人维护源，重新读取实际文件，检查结构、引用及变更；涉及脚本时运行适用验证。证据和验证范围要与报告一致。
6. **报告实际结果。** 在本轮结果中简述技能名、维护源路径、改进的方法及验证情况。已形成候选但未落盘时报告“未保存”与原因；没有新增价值时无需单独制造沉淀报告。

用户要求从当前经历或指定材料学习时，先按[显式学习](references/learn.md)盘点全部来源与要求，再返回上述流程。

## 复用

原生技能索引用于发现，正文与所需引用文件用于执行。索引或历史片段不足以支持修改；上下文压缩后缺失的正文应重新读取。

个人维护源与 runtime 冻结快照用途不同：写入维护源，新会话加载新版本；当前会话需要新经验时直接读取维护源，不假定当前索引已刷新。
